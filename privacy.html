01

What the extension stores on your device

All of this lives in Chrome’s local extension storage, on your machine. None of it is transmitted to us or to anyone else.

StoredWhy
Your Vault domainTo reconnect to the same Vault next time
Query historySo you can re-run recent VQL
Cached object and document-type metadataSo the data model browser and autocomplete work without re-fetching
Your AI provider API keyTo authenticate requests to the provider you chose

The API key is held by the extension’s background service worker and is never exposed to the extension’s own interface pages. It is sent only to the AI provider you selected, over HTTPS.

Delete it any time
RemoveDeletes the API key
ClearDeletes query history
UninstallRemoves everything Chrome stored for it
02

Your Vault session

To call the Vault API as you, the extension reads the Veeva Vault session cookie (TK) for the Vault domain you are signed in to. This cookie is used only to authenticate requests to that same Vault.

Never sent anywhere else
Never stored by the extension
No cookie read from any other site
03

The AI feature

Off until you enter an API key. When you ask a question, this is what leaves your browser — and nothing else.

To the provider you chose, on your own key
  • The question you typed
  • Documentation passages retrieved for it
  • A slice of your Vault’s configuration: object and field API names and types, document type names, and the VQL in the editor

docs.veevavault.dev receives the question only. No credentials are sent. Each answer shows exactly what was included, on the chip beside its citations.

Vault record data is never sent to an AI provider.

Query results, document contents and field values do not leave your browser.

Those services are governed by their own policies: Anthropic OpenAI Google AI
