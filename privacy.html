01

What the extension stores on your device

The following is held in Chrome’s local extension storage on your device. None of it is transmitted.

StoredPurpose
Vault domainReconnecting to the same Vault
Query historyRe-running recent VQL
Cached object and document-type metadataData model browsing and autocomplete without re-fetching
AI provider API keyAuthenticating requests to the provider you configure

The API key is held by the background service worker and is not exposed to the extension’s interface pages. It is transmitted only to the configured provider, over HTTPS.

Deletion
Remove — deletes the API key
Clear — deletes query history
Uninstall — removes all stored data
02

Your Vault session

The extension reads the Veeva Vault session cookie (TK) for the domain you are signed in to, and uses it to authenticate requests to that same Vault.

Not sent to any other destination
Not stored by the extension
No cookie read from any other site
03

The AI feature

No AI request is made until an API key is saved. When a question is submitted, the following is transmitted to the configured provider and nothing else:

  • The question text
  • Documentation passages retrieved for it
  • Schema metadata: object and field API names and types, document type names, and the VQL in the editor

docs.veevavault.dev receives the question text only; no credentials are sent. Each answer states what was included, beside its citations.

Vault record data is not sent to AI providers.

Query results, document contents and field values do not leave the browser.

Those services operate under their own policies: Anthropic OpenAI Google AI
